# Growth policy (Latch)

How we grow the project without spam or paid metrics.

## Principles

1. **Product first** — stars and downloads follow useful releases, not campaigns.
2. **No fake engagement** — never buy stars, reviews, or bot traffic.
3. **Honest listing** — only submit to directories / awesome-lists when Latch is a real fit and you maintain the link.
4. **Respect communities** — one thoughtful post per venue; follow each subreddit/forum’s rules; no cross-post blasts.
5. **Privacy holds** — growth features must not add trackers, ads, or required accounts.

## Allowed

- Clear README, screenshots, comparison table, Obtainium / release links
- `good first issue` / `help wanted` for real tasks
- F-Droid / IzzyOnDroid when metadata and builds are ready
- Occasional release notes on GitHub Discussions or your own site
- Answering users in issues

## Not allowed

- Star-exchange, follow-for-follow, or engagement pods
- Misleading claims (“Tasker killer”, guaranteed battery savings)
- Unsolicited mass DMs or issue spam on other repos
- Analytics SDKs “just to measure growth”

## Channels (when you post)

Prefer: GitHub Releases, project website, relevant FOSS Android threads, awesome-list PRs you will maintain.

Drafts may live under `docs/` but are **not** auto-posted.

## Beta vs stable

| | |
|--|--|
| **beta** | Day-to-day development; package `com.endroid.latch.beta` |
| **main** | Stable; package `com.endroid.latch` |

Promote beta → main for releases; tag `v*` for GitHub Release assets.
